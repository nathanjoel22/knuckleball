## Design

**The Pitches bubble (one component, three entry points).** A sheet over the charting screen (phone: bottom sheet in the U13 style; iPad/laptop: a centered card). It lists the pitcher's arsenal as chips in their type colors. Each row: the pitch name, **Edit accuracy** (opens the U14 painter for that pitch inline — exact cell plus up to four RA cells per batter side, with the vs RHB / vs LHB toggle), **Remove** (confirm; the pitch leaves the arsenal, past sessions untouched). Below the list: **Add a pitch**, a picker of the pitches not yet in the arsenal from the U3 list of 12, one tap adds it (RA cells empty until painted). Entry points: the "+" (P1) opens it on Add; holding a chip (P3) opens it scrolled to that pitch; Profile's existing Pitch mix section opens it the same way, so there is one editor, not two. The bubble works offline for the pitcher's own arsenal (changes queue like other profile edits); a coach's edits need a connection.

**Who may edit an arsenal.** The pitcher (own profile); the parent of a managed player (E3); **any coach who can currently see the pitcher** — `coach_sees_pitcher` from F1-A, which already encodes team coaches and facility group coaches and respects the narrowed R4. Server side this is one function, `set_pitch_arsenal(pitcher_id, pitches jsonb)`, SECURITY DEFINER, that checks exactly that predicate; the client never writes `profiles` pitch columns directly. Policy count unchanged if the existing self-update rule stays and the function covers the coach path.

**Relative accuracy edited mid-session.** U14 stores the hit kind on each pitch at tap time, so changing a pitch's RA cells during a session affects **later pitches only**; pitches already charted keep what they were scored against. The session's "Turn on Relative Accuracy?" answer is unchanged by edits; if RA was off for the session, the painter still saves to the profile but says "Relative accuracy is off for this session".

**Selected pitch after a removal.** If the removed pitch was selected, the selection clears and the next tap on a chip selects again; a pitch already thrown in this session stays in the session's rows and in the report even if removed from the arsenal afterwards.

**Perspective (E1 + P2).** The start question from U5 is removed: a bullpen opens behind the pitcher, a Live Game behind the catcher. The pitch-count line on phones gains a button reading **Catcher** or **Pitcher** (the side the charter is standing on); tapping flips it and re-renders labels and the plate exactly as the current drop-down does; after pitch 1 it shows the lock state and a tap explains "Perspective is set for this session". Discard or save clears it. iPad/laptop keep the perspective chips with the same lock. Stored coordinates still normalize to the catcher frame at capture (U5) — nothing about storage changes.

**Clock (E2).** The ⏱ control is removed from every charting screen (phones, iPad, laptop, bullpen and Live Game, both sports; softball never had it). `pitches.time_to_plate` stays in the schema and in reports for sessions that have it; no new values are written; the velocity bar's "< >" arrows and swipe are untouched. The History and report "time to home" lines keep rendering when the data exists and are omitted when a session has none.

**Pitcher switch (P4).** Coach only (a pitcher's own name is not a button). Tapping the name opens the roster picker. If the current session has no pitches it just switches. If it has pitches: the existing End session & save / Discard prompt. **Bullpen:** after save or discard, the new pitcher's bullpen starts. **Live Game:** after the current pitcher's session is saved, ask **"Continue the game from where you left off?"** — Yes starts the new pitcher's Live Game session with the same game (opponent, inning, outs, count, runners, score) through the R3 reliever path, so the departing pitcher is charged for his runners and the two sessions link as starter → reliever exactly as "Who was pitching?" does today; No starts a fresh game. Discard never offers continuation.

**Softball placement.** Softball phones have no Windup/Set, so the "+" sits where the delivery button would be, at the same size; everything else identical.

**Parent profile (E3).** On a managed player's profile the parent sees **Pitch mix** and **Relative accuracy** directly under Upload photo / Take photo, opening the same Pitches bubble. Adult pitchers' Profile is unchanged except that its Pitch mix section now opens the bubble.

## Decisions (recommended answers; Joel objects or they stand)

1. **Remove the U5 start question entirely** rather than defaulting it. Recommended yes: the button is the override, one tap, visible on the line the charter already looks at.
2. **Time to home is retired as a feature**, data kept. Recommended yes; if a coach asks for it later it returns as a per-team setting, not a default control.
3. **Who edits arsenals:** any coach who can currently see the pitcher (`coach_sees_pitcher`). Alternative: the recording team's coaches only. Recommended the former — a facility coach and a school coach both have a reason to add a pitch, and the pitcher sees every change.
4. **Mid-session RA edits apply to later pitches only.** Recommended; the alternative (rescore the whole session) contradicts the stored-per-pitch design and makes a report change under the charter's feet.
5. **Name-tap in a Live Game = pitching change through R3**, not a brand-new game with the state copied. Recommended; it is the only way inherited runners and the starter's line stay right.

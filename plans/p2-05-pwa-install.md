# P2-05 — Installable app: manifest, icons, home-screen install, splash (Oct 14, 2026)

**Joel, Oct 14, 2026.** Knuckleball installs to a phone's home screen like an app, opens full-screen with its own icon and splash, and keeps working with no signal. This is the ground the App Store wrapper (W1) stands on: the wrapper shows whatever the installed web app shows, so everything Apple and Google see — icon, name, splash, offline behavior — is settled here first.

## What ships

1. **Web app manifest** (`manifest.webmanifest`, linked from every page): name "Knuckleball", short name "Knuckleball", `start_url` the app, `display: standalone`, `theme_color` `--brand-bg` (`#061A12`), `background_color` `--bg` (`#F3F5F2`), orientation any, `id` set so updates stay one app. Icons: 192, 512, 512 maskable, plus Apple touch icon 180. Icons are the Knuckleball mark on the brand green, from `docs/design/target/` tokens; Joel approves the icon art before it ships (it becomes the store icon too).
2. **iOS specifics** (Safari ignores most of the manifest): `apple-mobile-web-app-capable`, `apple-mobile-web-app-status-bar-style: black-translucent`, `apple-touch-icon`, and a set of `apple-touch-startup-image` splash images for current iPhone and iPad sizes (generated from one SVG by a script in the repo; no third-party host). Safe-area insets honored on the session header and the coach dock (`env(safe-area-inset-*)`) so nothing sits under the notch or home bar in standalone mode.
3. **Service worker already exists (P1-01).** Confirm the manifest, icons and splash images are precached; confirm `start_url` loads offline on a cold launch; CACHE_VERSION bump.
4. **Install prompt, both platforms, in the app's own words:** a dismissible banner on Home (warning tint per DESIGN.md Banner) — Android: uses `beforeinstallprompt` to show one **Install** button (primary); iOS: explains Share → Add to Home Screen with the Share glyph, since Safari has no prompt. Shown once per device until dismissed or installed (localStorage); never on the charting screen.
5. **Standalone-mode polish:** no browser chrome means no back button — every screen reachable in standalone has an in-app Back; external links (privacy, terms, report links) open in the system browser, not inside the standalone window; pull-to-refresh disabled on the charting screen (`overscroll-behavior`) so a swipe doesn't reload mid-pen; the status bar reads the brand color.
6. **Update behavior:** when a new CACHE_VERSION is live, the app shows the existing "update available" affordance (or adds a quiet one) rather than silently serving stale pages for days in standalone mode.

## Decisions made in drafting (Joel may override)

1. One icon for both sports (the mark on brand green). The sport only changes inside the app.
2. The install banner is dismissible and never nags; a second prompt would come only from the getting-started page (P2-06).
3. Splash images are generated by a repo script from one SVG, committed as PNGs, so no build step is added to the site.
